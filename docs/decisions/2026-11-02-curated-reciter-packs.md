# قرار: حزم القرّاء المنسّقة وبطاقات التلاوة

- **الحالة:** ✅ **ACCEPTED** — 2026-11-02، المالك صادق على القرارات الأربعة
- **التاريخ:** 2026-11-02
- **المرجع:** `docs/superpowers/plans/2026-11-02-simulation-risk-remediation.md` §7 (Task 4)
- **المصدر التحليلي:** تقرير محاكاة MiroFish `report_2e78a6a6271f` (4 أقسام، 12 وكيل)

> لا يُكتب أي كود لهذه الميزة قبل وجود `reviewedBy` مُسمّى (D1). القرار معتمد، والتنفيذ مشروط.

## 0. ملخّص القرارات المعتمدة

| # | القرار | المعتمد |
|---|---|---|
| D1 | سلطة الانتقاء | **المالك + مراجع مُسمّى**؛ حقل `reviewedBy` إلزامي. قبل تسمية المراجع: v1 يبقى بلا حزم |
| D2 | المعايير | **الخمسة كما هي** (صحة الأداء بمراجعة بشرية، 114 سورة، جودة التسجيل، تنوع الأسلوب، لا معيار تجاري) وتُنشر في صفحة المبادئ |
| D3 | وزن الحزمة | **metadata فقط، 3–7 قرّاء**؛ لا صوت مضمَّن، streaming افتراضي، التنزيل لكل سورة بقرار المستخدم |
| D4 | بطاقات التلاوة | **مؤجّلة إلى v2**؛ v1 = قوائم منسّقة فقط |

**حالة التنفيذ:** لا شيء يُبنى الآن — الميزة موقوفة على تسمية المراجع (D1).


## 1. السياق — ما هو موجود فعلاً

| المكوّن | الواقع في الكود |
|---|---|
| كتالوج القرّاء | من **mp3quran API**، صف لكل (قارئ × مصحف): `id = <reciterId>-<moshafId>`, `reciterName`, `moshafName`, `server`, `surahList`, `surahTotal` — `lib/core/db/*` (`ReciterRow`) |
| الصوت | **streaming** عبر `server + surahN.mp3` (`surahAudioUrl`)، والتنزيل لكل سورة بسقف بايت (`audio_downloader.dart`) |
| «pack» موجود بالفعل | حزم **محتوى** (تفسير/ترجمة/حديث): كتالوج JSON مضمَّن + sha256 + seam لمانيفست بعيد — `lib/features/library/data/library_catalog.dart` |
| المشاركة | مشاركة **نص آية** فقط (`share_plus` في `reader_screen.dart`) — لا بطاقات |
| صفحة المبادئ | أُضيفت في هذه الموجة (`principles_screen.dart`) — المكان الطبيعي لنشر معايير الانتقاء |

**الخلاصة:** الميزة ممكنة بدون أي محتوى صوتي جديد. «الحزمة» = **قائمة انتقاء (metadata)**: معرّفات قرّاء + سبب الاختيار + وصف مختصر. لا تُضمَّن أصوات، ولا تُغيّر مسار التنزيل الحالي.

## 2. ما ليست عليه الميزة (حدود غير قابلة للتفاوض)

1. ليست حزم صوتية جديدة ولا ملفات تُضمَّن في APK/IPA.
2. ليست ترتيبًا خوارزميًا يُقدَّم كـ«توصية شرعية».
3. ليست قناة إعلانات أو ترتيبًا مدفوعًا — ولو لاحقًا، تُفصح عنه صراحةً.
4. لا تتبّع لسلوك الاستماع، ولا ملفات تفضيل تُبنى على الخادم.

## 3. القرارات المطلوبة

### D1 — سلطة الانتقاء (من يوقّع؟)

| الخيار | الأثر |
|---|---|
| **(أ) المالك وحده** | أسرع، صفر حوكمة. خطر: لا يوجد فحص تجويد مستقل، وهو جوهر اعتراض المعلمين في المحاكاة |
| **(ب) المالك + مراجع مُسمّى (مقرئ/شيخ)** ✅ *موصى به* | يطابق شرط «الكلمة الأخيرة للمراجعة البشرية»؛ يضيف خطوة واحدة لكل حزمة |
| (ج) ترتيب مجتمعي/خوارزمي | مرفوض: يحوّل الاقتراح إلى تزكية بلا مسؤول |

**التوصية (ب).** الحقل `reviewedBy` إلزامي في الكتالوج. **قبل** وجود مراجع مُسمّى: يُطلق v1 **بدون أي حزمة** (القائمة الحالية كما هي).

**الأثر لو غلطنا:** سحب حزمة = تعديل كتالوج واحد + سطر في سجل التغييرات.

> **المعتمد:** (ب) — المالك + مراجع مُسمّى.

### D2 — المعايير المنشورة (خمسة، غير تجارية)

1. صحة الأداء ومخارج الحروف — **مراجعة بشرية** قبل الإدراج.
2. اكتمال المصحف — `surahTotal == 114` (فحص آلي متاح).
3. جودة التسجيل وثباته — استماع يدوي لعيّنة.
4. تنوّع الأسلوب (مرتل/مجوّد/معلّم) — من `moshafName`.
5. لا معيار تجاري، ولا ترتيب مقابل مقابل مادي.

**التوصية:** نشر الخمسة في صفحة المبادئ (موجودة) + في وصف كل حزمة.

> **المعتمد:** الخمسة كما هي.

### D3 — وزن الحزمة

**التوصية:** حزمة = **metadata فقط** (‏1–2 KB): 3–7 قرّاء، وصف سطرين، `reviewedBy`، `updatedAt`.
- لا صوت مضمَّن؛ الاستماع streaming افتراضيًا.
- التنزيل يبقى قرار المستخدم لكل سورة كما هو.
- سقف صلب: أي حزمة تتجاوز 7 قرّاء تُرفض في التحقق (نفس نمط `_packIdPattern`/sha في حزم المكتبة).

> **المعتمد:** metadata فقط، 3–7 قرّاء، بلا صوت مضمَّن.

### D4 — البطاقات القابلة للمشاركة

موجود اليوم: مشاركة نص الآية. المقترح (v2، **مؤجّل** حتى تُغلق D1–D3):

- البطاقة تُولَّد **محليًا** (بلا خادم) وتحمل: اسم القارئ + المصحف + السورة/الآية + المصدر (mp3quran).
- نص ثابت: **«مشاركة ≠ تزكية»**.
- بلا شعار مائي فوق نص الآية (تحفّظ فئوي ذُكر صريحًا في المحاكاة).
- بلا أي رمز تتبّع أو رابط قصير مُقنَّع.

**التوصية:** تأجيل البطاقات إلى v2، وإطلاق v1 = قوائم منسّقة فقط.

> **المعتمد:** تأجيل إلى v2.

## 4. ما لا يشمله هذا القرار

- إشعارات «حزمة الأسبوع» (تحتاج قرار إشعار منفصل — بوابة الإشعارات أُضيفت للتو).
- أي نموذج مدفوع أو اشتراك (سياسة منفصلة).
- تعديل كتالوج mp3quran أو إعادة استضافة الصوت.

## 5. عند الاعتماد — قائمة الإطلاق

1. جدول/حقل `reviewedBy` + تحقق السقف في طبقة البيانات (لا في الواجهة).
2. صفحة «حزم القرّاء» تعرض الوصف والمعايير و«مَن راجعها».
3. اختبارات: رفض حزمة > 7، رفض بلا `reviewedBy`، رفض معرّف غير موجود في الكتالوج.
4. سطر في سجل التغييرات لكل إضافة/سحب حزمة.

## 6. المطلوب لبدء التنفيذ (خارج نطاق Task 4)

Task 4 انتهى بقرار، **ولم يُبنَ كود**. لفتح التنفيذ يلزم من المالك:

1. **اسم المراجع** (`reviewedBy`) وجهة اتصاله — ولو مؤقتًا لمراجعة أول حزمة.
2. **أول حزمة**: 3–7 معرّفات قرّاء موجودة فعلاً في كتالوج mp3quran + سبب الاختيار.

بعدها تُكتب خطة تنفيذ جديدة (كتالوج + تحقق + صفحة + اختبارات) على نمط حزم المكتبة.
