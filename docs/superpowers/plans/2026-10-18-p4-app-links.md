## 3. `lib/app/deep_links.dart` (deliverable 2 — pure logic, no Flutter imports)

- `String? deepLinkRouteFor(Uri uri)` — null unless scheme `https` AND host `quranyahdi.pages.dev`. Mapping table (EXACT — tests pin every row):

| Input path (on the host) | Result |
|---|---|
| `/surah/{n}`, n ∈ 1..114 | `/quran/reader?surah={n}` |
| + fragment `#ayah-{m}`, m ≥ 1 | `/quran/reader?surah={n}&ayah={m}` |
| `/surah/{x}` invalid n (0, 115, non-numeric) | null |
| trailing slash tolerated (`/surah/36/` == `/surah/36`) | as above |
| absent/invalid fragment (`#ayah-0`, `#x`) | surah-only route |
| `/quran`, `/quran/` | `/quran` |
| `/reciters`, `/reciters/` | `/recitation` |
| anything else (`/`, `/about`, …) | null |

- `String webSurahUrl(int surah, [int? ayah])` — `https://quranyahdi.pages.dev/surah/{surah}` + `#ayah-{m}` when `ayah != null`. Byte-format mirror of `web/src/lib/urls.ts` (the shared link must deep-link back into the app on another device — that is the acceptance property).
- Do NOT validate ayah against the surah's ayah count here — the reader route's existing contract handles out-of-range.
