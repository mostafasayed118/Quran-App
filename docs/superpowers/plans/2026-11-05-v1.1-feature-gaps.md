# v1.1 feature-gap program — implementation plan

> **Status:** Wave A (reader line spacing, Hijri ±1, prayer tuning), Wave B
> (player controls, ayah image share, download-all) and C1 (Ramadan timetable +
> missed-fast tracker) are **implemented** on 2026-11-05: 9 features, gates
> **1344/1344** · format 0 · analyze 0. Wave A+B is committed as `1c67d2d`;
> C1 is in the working tree awaiting its own commit window. Waves C2/C3 and D
> are not started.
>
> **Goal:** close the user-facing gaps found by the 2026-11-05 feature audit,
> without adding unlicensed content and without weakening any frozen test.

## Scope split

### Buildable now (code only)

| Wave | Feature | Why it is safe |
|---|---|---|
| A1 | Reader line spacing | one setting, no content, no schema |
| A2 | Hijri date ±1 adjustment | one setting, pure conversion |
| A3 | Per-prayer minute offsets + high-latitude rule | pure `adhan` parameters, persisted settings |
| B1 | Player: repeat, speed, sleep timer, next/previous surah | `just_audio` capabilities already available |
| B2 | Share an ayah as a rendered image card | `share_plus` + `path_provider` already dependencies |
| B3 | Download every surah of a reciter | reuses the existing download queue |
| C1 | Ramadan: imsak/iftar times + imsakiah month view + qada tracker | pure calculation + local DB; no fiqh content |
| C2 | Home-screen prayer widget | `home_widget` grant ratified in D3 |
| C3 | Escalating Fajr alarm + forbidden-times info | notification + static content |
| D1 | Tafsir single-file install + reclassify the shipped Siraj pack | pipeline already supports the read side |
| D2 | Search installed translations | local pack files, no network |
| D3 | Bookmark folders/notes | schema v4, owner decision recorded below |
| D4 | Hadith search + bookmark + position memory | local pack files + schema v4 |

### Blocked — do not code

| Item | Blocker |
|---|---|
| Word-by-word meanings | clean licence (D2 licence-first rule) |

### Rejected — do not reopen

extra site languages · zakat input persistence (D8).

## Decisions taken for this program

1. **No new packages** in waves A and B. Wave C2 uses `home_widget` under the
   already-ratified D3 grant; it is the only addition.
2. **Schema v4** is allowed in wave C1/D3 for the qada table and bookmark
   folders. It ships with a stepwise migration test and a rebuilt DB asset if
   the bundled schema changes; the drift gate must stay green.
3. **Reader line spacing is the only reader-display addition.** Font choice is
   deliberately out: the Unicode Uthmani text depends on HafsSmart; me_quran is
   a PUA glyph face, not a general text font.
4. **Hijri offset and prayer tuning are user preferences**, so they join the
   backup whitelist (Class B pin extension). They are not device-scoped.
5. **Ramadan ships no fiqh text.** The times, the month view and the qada
   counter are calculation/state; a fasting-rules pack is content-review work.
6. **Strictly additive l10n.** New ARB keys in `ar` + `en`, generated files
   regenerated, no existing value edited.
7. **No frozen behaviour pin is edited.** New behaviour gets new test files;
   only Class B inventory pins (backup whitelist, route map, l10n surface) may
   be extended with a recorded delta.

## Gates (every wave)

- `dart format --set-exit-if-changed lib test tools` → 0
- `flutter analyze` → 0
- full `flutter test` → exact count, no failures
- `melos`-style architecture guard (`test/architecture_guard_test.dart`) green
- generated files (`*.freezed.dart`, l10n) regenerated and committed with the
  code that needs them
- no new dependency without a grant
- no push

## Wave A — accuracy and reading comfort

### A1 Reader line spacing

- `ReaderLayoutSource` (new, segregated from `ReaderSettingsSource` so every
  existing test double keeps compiling): `loadLineHeight()`, `saveLineHeight()`.
- `ReaderSettingsRepository` implements it; key `reader_line_height`,
  clamped 1.6–3.0, default 2.2.
- `ReaderReady.lineHeight` default 2.2; `ReaderCubit.setLineHeight`.
- Font sheet gains a second labelled slider; the verse and mushaf styles read
  `state.lineHeight`.
- Tests: repository round-trip/clamp; cubit clamp/persist; the existing font
  sheet still opens.

### A2 Hijri ±1

- `HijriService.offsetDays` applied in `fromGregorian` (+offset) and
  `toGregorian` (−offset); `daysInMonth` and `monthName` stay pure.
- `HijriOffsetSource` + repository (`hijri_day_offset`, −2..+2, default 0).
- `HijriCubit` loads the offset before the first show and exposes
  `setOffset`; the screen gains a compact −/+ row with the current value.
- Tests: the service shifts both directions across a month boundary; the
  repository clamps; the cubit applies and re-renders.

### A3 Prayer tuning

- `PrayerConfig` gains `adjustments` (five prayers, −30..+30 minutes) and
  `highLatitude` (`none`, `middleOfTheNight`, `seventhOfTheNight`,
  `twilightAngle`), both with historical defaults.
- `prayer_calculator.parametersFor` sets `parameters.adjustments` and
  `parameters.highLatitudeRule`.
- `PrayerConfigCubit` gains `setAdjustment` and `setHighLatitude`.
- `PrayerConfigScreen` gains a "ضبط دقيق" section: one row per prayer with −/+
  and a four-option high-latitude control.
- Backup whitelist + reminder-relevant keys learn the two new keys (offsets
  change the computed times, so a restore must re-plan).
- Tests: serialization/equality; calculator applies a +5 Fajr offset and the
  high-latitude rule; cubit persists; backup pins updated.

## Wave B — listening and sharing

### B1 Player controls

- `PlaybackState` gains `speed` (default 1.0), `repeatMode` (off/one) and
  `sleepTimer` (nullable duration), all defaulted so existing constructors and
  frozen doubles compile.
- `PlaybackService` capability methods `setSpeed` / `setLoopMode`; the
  just_audio adapter implements them.
- Cubit: `setSpeed` (0.75/1.0/1.25/1.5/2.0), `toggleRepeat`, `startSleepTimer`
  (15/30/45/60 min), `cancelSleepTimer`, `nextSurah`, `previousSurah`.
- Completion: repeat-one replays; otherwise next surah; otherwise stop.
- UI: a control row in the player sheet; the mini player keeps its current
  surface.
- Tests: speed reaches the service; repeat replays; sleep timer pauses under
  `fakeAsync`; next/previous clamp at 1 and 114.

### B2 Ayah image card

- A `VerseCard` widget (surah name, ayah text, ayah number, app wordmark) and a
  preview sheet with a share action.
- Capture through `RepaintBoundary.toImage` → PNG → `getTemporaryDirectory` →
  `SharePlus.instance.share(files:)`.
- A `VerseImageSharer` seam so widget tests can assert the file request without
  the platform channel.
- Tests: the card renders the text/attribution; the captured bytes start with
  the PNG signature; a capture failure falls back to the existing text share.

### B3 Whole-reciter download

- A "تنزيل كل السور" action on the reciter screen; it enqueues every surah the
  moshaf offers that is not already downloaded.
- Tests: enqueues only missing surahs, is idempotent while the queue runs.

## Wave C — Ramadan and visibility

### C1 Ramadan

- Imsak = Fajr − 10 min (clamped 0..30); iftar = Maghrib.
- The current Ramadan month, or the next one after it ends; a today card and
  one row per day.
- Qada tracker: a settings JSON row (`qada_missed_fasts_v1`) rather than
  schema v4 — the set is tiny and follows the azkar/tasbih precedent. It joins
  the backup whitelist.
- Tests: the imsak/iftar math, the current/next month choice, the row anchors,
  and the qada round-trip/add/remove/revert.

### C2 Home-screen widget

- `home_widget` + one Android `AppWidgetProvider` (next prayer + countdown).
- The app pushes a snapshot on every successful re-plan and on boot.
- Device verification is required before calling it done.

### C3 Notification polish

- Escalating Fajr: the Fajr reminder repeats at a short interval until opened
  or the window ends (bounded, no infinite alarm).
- Forbidden-times info card (static windows computed from the day's times).
- Tests: the escalation plan is bounded; the windows are correct for a known
  day.

## Wave D — library and study

### D1 Tafsir single-file

- `LibraryPackInfo` accepts a tafsir with `sourceUrl` (single file) as well as
  `urlTemplate` + `fileCount`; the integrity gate requires `sha256` for the
  former and `sha256PerSurah` for the latter.
- Install routes a single-file tafsir through the single-file writer; the read
  path accepts the edition's `quran`/`ayahs` shape for tafsir.
- Reclassify `ara-sirajtafseer` to `kind: tafsir`; the tafsir tab and the ayah
  sheet tab become visible.
- Tests: catalog parse for both shapes, install sniff, read path, tab visibility.

### D2 Translation search

- Index installed translation packs by normalized text; the search screen gains
  a source filter (Quran / installed translations).
- Tests: normalization, paging, no-pack fallback.

### D3 Bookmarks

- Schema v4 folders + notes; the flat list keeps working when no folder exists.
- Tests: migration, folder CRUD, backup export/import.

### D4 Hadith

- Search over the installed hadith pack, bookmark a hadith, remember the last
  page.
- Tests: search, bookmark round-trip, position restore.

## Review focus

1. A restored backup must not shift prayer times silently — the two tuning keys
   are reminder-relevant and re-plan.
2. A malformed persisted value must never crash the reader/hijri/prayer screens.
3. The sleep timer must not outlive the player or fire after a stop.
4. An image-capture failure must still share the text, never nothing.
5. A single-file tafsir must pass the same sha256 gate as every other pack.
