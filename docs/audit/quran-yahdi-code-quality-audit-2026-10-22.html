01

Executive summary

35 verified findings · 1 high · 17 medium · 17 low

What stands out

  • Clean gates: analyzer, formatter, and the full 600-test suite are green.
  • Enforced boundaries: zero cross-feature imports, zero core-to-feature imports.
  • Consistent failure contract: localized copy only; diagnostics go to dev.log.
  • Security depth: pinned remote content, parameterized SQL, no tracked secrets, hardened CSP.

What needs attention

  • Pack memory: the reader cache is bounded by entry count, not bytes; large tafsir packs can stay resident.
  • Main-isolate work: install-time hashing and backup encoding can cause dropped frames.
  • Silent failure paths: settings mutations and some boot hooks can fail without feedback or logs.
  • Seam erosion: the router acts as a second composition root; backup writes other features' tables directly.

First actions

  • Byte-budget the pack cache and project hadith to compact records.
  • Move install hashing and backup encoding into worker isolates.
  • Batch backup writes inside the existing transaction.
  • Guard settings mutations with logging and an explicit failure state.

03

Top 5 priority issues

Ranked by risk to users and release quality

1
High

Pack cache retains full text projections

Performance

The projection cache is bounded by entry count (2), not bytes. Hadith packs are stored as the raw decoded list and tafsir packs as a full ayah-to-text map, so a large installed pack can remain resident indefinitely.

lib/features/library/data/pack_reader.dart:39‑41,99,127‑128 · catalog: Bukhari 9.4 MB, Ibn Kathir tafsir 82 MB (assets/data/library_catalog.json)

Fix: enforce an approximate byte budget, project hadith to List<(int, String)>, and evict the tafsir projection when the ayah sheet closes.

2
Medium

Install pipeline does heavy work on the UI isolate

Performance

Each tafsir batch buffers four complete surah bodies, verifies SHA-256 on the UI isolate, then builds the merged index on the same isolate. Large packs can drop frames during install.

pack_downloader.dart:184‑207,202,255‑263,367 · pack_downloader_types.dart:39 (_tafsirBatchSize = 4)

Fix: stream each body into the hashing sink inside the worker isolate, reduce the batch to 2, and return a compact projection.

3
Medium

Backup restore writes row-by-row; export encodes on the UI isolate

Performance

Import performs one awaited statement per row inside a transaction, so thousands of bookmarks or prayer days become thousands of isolate round-trips. Export runs jsonEncode on the UI isolate even though import decoding is already isolated.

lib/features/backup/data/backup_service.dart:42‑49,220‑266

Fix: write through _db.batch((b) => b.insertAll(...)) and move export encoding into Isolate.run.

4
Medium

Settings mutations can fail silently

Reliability

setAzkarEnabled, setTime, toggleWird, and changeWirdTime have no error handling, while the screen calls them fire-and-forget. A failed SQLite write becomes an unhandled async error with no user feedback and no diagnostic.

settings_cubit.dart:67‑126 · callers at settings_screen.dart:79,86,92,99

Fix: wrap each mutation, log through dev.log, and expose an explicit failure or permissionDenied field. Apply the same discipline to cached_loader.dart:14‑17, which currently loses the original stack trace.

5
Medium

CI publishes debug-signed “release” artifacts

Security · supply chain

CI builds ‑‑release without a keystore, silently falls back to the debug signing config, and uploads the result as app‑release‑apk / app‑release‑aab. The artifact cannot be updated by a future store build and is not attributable to the owner key.

.github/workflows/ci.yml:41‑52 · android/app/build.gradle:89 — known and documented as W7c-pending.

Fix: upload only when the keystore exists and PUBLISH_RELEASE=true; otherwise skip the upload or name the artifact debug‑signed‑do‑not‑distribute.

The fallback is silent, so the artifact looks official but cannot be updated by a future store build. .github/workflows/ci.yml:41‑52; android/app/build.gradle:89; documented W7c-pending in AGENTS.md §4. A crafted 2 MB backup can write out-of-range ayah ids or absurd page targets. backup_codec.dart:308‑313,331‑338; inserts at backup_merger.dart:35, backup_service.dart:222. Enforce 1..6236 for ayah ids, 1..604 for pages, and bound tasbih values and list lengths.

Dimension notes

What works — and what to watch

01 Maintainability

8.0 /10

One enforced feature shape across 16 modules, with 2,564 lines of doc comments that explain invariants rather than restating code. The main drags are test organization and two multi-role classes.

  • Works: small private widgets, zero print/TODO/force-unwraps, documented rationale.
  • Watch: duplicated test doubles, flat test tree, downloader/registry coupling.
7 findings · 4 medium · 3 low

02 Clean Architecture

7.5 /10

A genuine feature-first architecture with ports at every cross-feature seam, a single documented composition root, and an allowlist-pinned guard test. The pressure points are duplicated wiring and a few leaks.

  • Works: zero cross-feature imports, route-scoped cubits registered as factories, ports for prayer times and reminders.
  • Watch: router-as-composition-root, backup bypassing owning repositories, drift row leaking into presentation.
8 findings · 5 medium · 3 low

03 Code Quality

8.5 /10

Strict analyzer settings, no dead code or debug output, and a uniform Loading / Ready / Failed contract with localized copy only. Residual debt is robustness and diagnostics, not structure.

  • Works: strict‑casts, unawaited_futures, cancel_subscriptions; shared empty/loading/error widgets.
  • Watch: lost stack traces, unguarded settings writes, positional casts.
6 findings · 3 medium · 3 low

04 Security

8.5 /10

No critical or high vulnerability. Untrusted-input paths are genuinely hardened: size caps, hash pins, host allowlists, fail-closed parsing, and parameterized SQL. Residual risk is release signing and small validation gaps.

  • Works: no tracked secrets or keystores, no WebView, no cleartext, CSP without unsafe‑inline.
  • Watch: debug-signed CI artifacts, backup integer ranges, redirect validation.
6 findings · 1 medium · 5 low · 6 verified controls

05 Performance

7.5 /10

SQLite runs on drift’s background isolate, pack JSON decodes in workers, and rebuild scoping is deliberate. The real risks are memory retention in the library cache and main-isolate work in two write-heavy flows.

  • Works: WAL, background database, worker decode, per-verse selectors, no leaked subscriptions.
  • Watch: byte-unbounded pack cache, install-time hashing, per-row backup writes, per-tap tasbih writes.
8 findings · 1 high · 4 medium · 3 low

Security controls verified

Checked directly, not inferred

✓

Secrets & signing material

No tracked keystores, key.properties, .env, or local.properties; zero API-key, token, or private-key matches in the repository.

✓

Backup & deep links

allowBackup=false; deep links are restricted to the official host and path prefixes and re-validated in code; exported media components are signature-permission guarded.

✓

Injection surface

All drift raw SQL is parameter-bound; no WebView, JS bridge, or eval; pack paths are regex-gated twice with no archive extraction (no zip-slip).

✓

Remote content integrity

Packs are SHA-256 pinned (per surah for tafsir), size-capped, host-allowlisted, and written-then-promoted. Backup imports are capped at 2 MB with format guards and a settings whitelist.

✓

Web hardening

CSP uses script‑src 'self' with exactly four hashes and no unsafe‑inline; HSTS, nosniff, DENY, and frame-ancestors are present, pinned by a unit test.

✓

Network

No cleartext URLs in lib/, no TLS-verification overrides, and no certificate bypass code paths.

Method & limitations

How the result was produced

1 Baseline & gates

  • Recorded HEAD, working-tree state, and toolchain versions.
  • Ran flutter analyze, the full flutter test suite, and dart format ‑‑set‑exit‑if‑changed.
  • Scripted scans counted files, lines, largest files, and every import edge.

2 Parallel dimension review

  • Five read-only reviewers, one per dimension, each capped to a focused file sample.
  • Each reviewer required to cite file:line and a concrete fix.
  • Claims were treated as hypotheses, not conclusions.

3 Source verification

  • Every high-impact claim was reopened at the cited line and quoted.
  • Five claims were corrected or downgraded; the corrections are published above.
  • Security checks were run directly: tracked-file scan, manifest review, SQL and secret greps.

4 Scoring

  • Each dimension scored 0–10 against the repository’s own governance rules.
  • Weights: 20% maintainability, 20% architecture, 20% code quality, 25% security, 15% performance.
  • The arithmetic is shown so the total can be recomputed.
Limitations. No profiler or physical device was available: memory and jank figures are estimates derived from catalog sizes and code paths. No CVE/OSV database scan was run; pub outdated shows only patch-level drift in direct dependencies. Generated files (*.g.dart, *.freezed.dart, localization output) were excluded from style and debt judgments. The web and native shells were reviewed for security posture, not feature behavior.
